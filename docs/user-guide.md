# 艾泽拉斯周计划使用说明

## 第一次打开

打开 Windows 安装包，或直接运行 `release/win-unpacked/艾泽拉斯周计划.exe`。直接运行时必须保留该目录内的其他文件。

初次启动没有角色数据。可以点击“先看看演示”试用界面；演示数据有醒目标记，所有修改仅在内存里，退出演示后回到你的实际记录。

## 安装游戏采集插件

1. 解压 `dist/addon/AzerothWeekly.zip`。
2. 将其中的 `AzerothWeekly` 文件夹放到 `D:\World of Warcraft\_retail_\Interface\AddOns\`。
3. 检查最终路径为 `D:\World of Warcraft\_retail_\Interface\AddOns\AzerothWeekly\AzerothWeekly.toc`，避免套了两层同名文件夹。
4. 打开游戏，在插件列表启用 AzerothWeekly。当前包按已读取的国服 12.1.5 客户端 Interface 120105 配置。
5. 分别登录四个子账号中需要追踪的角色。每个角色至少登录一次，插件才能采集该角色。
6. 输入 `/reload`，或正常切换角色／退出游戏，让游戏把插件数据写入磁盘。

开发过程中没有自动修改你的游戏目录，以上安装步骤需要自行完成。

## 配置四个导入来源

进入“同步与备份”，点击“选择游戏目录”，选择 `D:\World of Warcraft` 或其 `_retail_` 子文件夹。

本机目前有五个账号存档目录，可能包含旧目录。勾选实际使用的四个来源，点击“保存来源选择”。先登录并保存过插件数据的目录会显示“已发现插件存档”，可帮助识别有效来源。

目录位置是 `_retail_\WTF\Account\<来源目录>\SavedVariables\AzerothWeekly.lua`。来源目录只在导入设置中展示；角色总览、团本计划和币账本都统一展示角色，不按子账号分组。

软件运行时约每 8 秒检查已选来源。也可以点击“立即读取”或“手动选择存档文件”。“读取”只能获取已保存到磁盘的数据，不能强制游戏保存内存中的进度。

同一角色重复导入会合并，事件按持久 ID 去重。角色以 GUID 归属，同名角色不会被随意合并。每条进度显示采集时间；旧存档不会被标成刚完成的活动。

## 设置宏伟宝库目标

每个角色的每周目标固定为：**任意活动合计解锁 3 个格子**。例如团本 2 格加地下城 1 格即达标，不要求同一行开满，也不限制奖励装等。总览每个角色显示 0/3 至 3/3，顶部显示达标角色数。点击“查看宝库目标”可查看规则和当前进度。

当周栏位由插件读取，不把示例中的次数或装等固定为游戏规则。宝库计入所有游戏有效活动，包括未加入 BOSS 计划的活动。上一周是否有奖励可领取与本周积累分别展示。

“待同步”“未完成”和“已完成”含义不同。数据未知时不会当成零进度，也不会计算为达标。多个解锁栏位表示多个可选奖励，不表示可同时领取多件。

## 制定 BOSS 周计划

点击“添加 BOSS 计划”，选择要应用的角色、当前赛季团队副本、难度和 BOSS。选择器包含游戏内冒险指南“当前赛季”的全部团本，隐藏同资料片的旧赛季及以前资料片团本。可以填写目标装备，并勾选是否准备在该 BOSS 使用 ROLL 币。

列表只显示你加入计划的 BOSS。打了计划外的 BOSS，不会把它自动加入列表。同一 BOSS 的不同难度分开设置，重复加入相同目标会跳过。

用币意向不会扣除余额；“实际消耗”来自已确认的用币流水。击杀状态和拾取资格是独立字段；没有可靠拾取资格时显示“未知”。

可以编辑或移除计划。移除计划保留原有击杀事实和币流水。新一周可以点击“复制上周目标”，只复制仍属当前赛季的 BOSS 目标和意向，跳过旧赛季团本，不复制完成状态或实际消耗。旧计划、击杀事实和币流水继续保留。

升级到 0.1.2 时需要同时更新桌面软件和 AzerothWeekly 插件。旧存档没有当前赛季标记时不会列出历史团本供新增计划选择；如界面提示当前赛季目录尚未采集，在游戏中输入 `/azweekly catalog`，再 `/reload` 并读取存档。目录来自客户端，不会在真实模式填入虚构 BOSS。

## 使用 ROLL 币账本

选择角色，查看最近可靠的持币余额和当周已记录获取／消耗。余额与流水分开保存，初次读取的 3 枚余额不会被虚构成过去三次获取记录。

0.1.2 已修复多货币存档中误取第一项货币余额的问题。总览、角色行和账本只按当前 ROLL 币 ID 取值，忽略其他货币和旧赛季的币种 ID。真实余额 0 显示为 0，未能读取或名称不匹配显示“—／待确认”；旧记录和其他币种流水保留，但其他币种不计入 ROLL 币获取／消耗合计。可在游戏中输入 `/azweekly currency 3513`，查看实际返回的币名和数量，再 `/reload` 后读取进度核对。

当前插件支持对符合实际名称的晦暗虚空核心币种读取余额（12.1.5 候选币种 3513）。具体国服余额返回仍需首次游戏采集核对，不会把旧币种 3418 的余额套到新币种上。

额外拾取事件目前仅保存为待核对观察，不能凭“币少了”或“刚打了某个 BOSS”推断消耗归属。点击“记录一笔”，填写时间、获取／消耗方向、数量、来源，按需关联团本、难度、BOSS、奖励和装等。计划外的 BOSS 也能在账本中记录。

手动补录不会覆盖游戏采集余额。发现流水填错时点击“更正”，软件保存单独的人工更正记录，保留最初的原始记录。待核对事件不计入已确认获取／消耗统计。

如果余额无法读取，可用 `/azweekly` 检查诊断。高级排查可以使用 `/azweekly currency 3513` 后 `/reload`；若客户端返回不可靠，界面继续显示未知。

## 每周切换与历史

右上角选择游戏周。“历史进度”可以回看已有快照。游戏周以客户端重置数据为依据，离线推算的周期会标注待确认。收到实际重置边界后，会校正对应推算周期中的目标关联。

新周没有新采集的角色显示待同步。持币余额是跨周持有量，不会随周切换清零；历史界面仍明确显示余额的实际采集时间。

## 备份与恢复

“导出完整备份”保存角色、备注、计划、采集记录、流水、更正记录和来源映射。备份保存在你选择的位置。

恢复会替换当前数据库。软件在恢复前自动生成安全副本，校验失败时保留原数据库。恢复后来源不会自动获得读取权限，需要重新选择游戏目录和来源。

“导出币流水 CSV”用于表格查看，以人工更正后的有效流水导出。CSV 不能代替完整 JSON 备份。

## 当前验证范围

已验证协议、实际 Lua 插件在模拟客户端中的运行、受限 Lua 数据解析、SQLite 事务、来源选择、界面交互、桌面进程与业务接口。

尚未自动执行真实游戏登录、四个子账号跨登录采集、真实周重置、真实击杀或额外拾取。这些需要使用插件后在游戏内核对。详细清单见 `docs/testing/real-client-checklist.md`。
