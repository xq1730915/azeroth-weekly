## 已实现的行为

- 四来源导入与统一角色展示；角色归属使用 GUID，来源只在导入设置中出现。
- 宏伟宝库按每个角色任意活动合计解锁 3 格达标，支持跨活动累计、去重、冲突和过期数据待确认；上一奖励周期状态单独记录。旧栏位目标数据保留用于备份兼容。
- 手动选择角色／当前赛季团本／难度／BOSS，增删改计划、批量应用。当前赛季 ID 从客户端冒险指南采集；旧存档没有赛季标记时提示重新采集。复制上周计划会跳过旧赛季团本，完整目录和历史记录保留。同步不会加入计划外 BOSS。
- ROLL 币余额、获取／消耗／调整流水、BOSS／难度／奖励／装等关联，手动补录和单独保存的人工更正。计划删除不会删除流水。
- 受限 Lua 数据语法解析和协议校验，不执行导入文件里的 Lua。
- SQLite 事务、四来源角色合并、重复事件去重、旧快照保护、同秒序列更新和推算周目标校正。
- 定时读取选定来源、手动读取文件、来源错误诊断、每周历史、JSON 备份恢复、CSV 导出。
- 独立演示模式。演示使用内存数据库，退出后回到实际数据库，不向实际记录写入示例角色。
- Windows 安装包与完整免安装包，游戏插件压缩包。

## 0.1.2 余额修复

已复现并修复：旧插件采集多种货币，桌面用第一项余额代表 ROLL 币，导致持币数量取错。插件现只导出经过客户端名称校验的候选 ROLL 币；桌面按币种 ID 选择最新记录，总览、角色行、账本和 BOSS 用币量保持一致。0 与未知分别处理，未知不会回退到其他币种或旧余额。其他币种历史流水保留并标注，不计入 ROLL 币合计。

只读核对用户软件已导入数据库：两个角色的旧选择均为其他货币，新选择均指向 currency:3513；没有修改用户数据库或游戏目录。新的 Lua 货币隔离测试在修复前失败，修复后通过。

## 0.1.1 目标与团本范围升级

用户确认宝库为任意活动合计开三格，团本范围为当前赛季全部正式团本。客户端 Current Season 目录与全量历史目录分别保存；不会用数字最大的团本或最新资料片代替赛季判断。季目录选择失败时保持未验证并提示重新采集。

升级步骤：安装最新桌面软件，同时替换游戏 AzerothWeekly 插件，登录角色输入 `/azweekly catalog`，再 `/reload` 后读取进度。真实游戏返回和赛季目录内容仍待首次登录验证。

## 已发现并修复的问题

独立子代理审查发现两项重要问题：按重置结束时刻生成周 ID 会因跨秒采样或维护调整丢失击杀事实；用两个不同时间采样做相等判断会丢弃正确的击杀事件。

已改为优先使用客户端确认的周起点作稳定身份，对推算周期保留显式不确定性；击杀处理使用本次实际返回的新快照及事件时间。三项新增 Lua 回归测试先失败、修复后通过。

后续验证还处理了同秒但更高序列的采集更新、服务端确认推算周后的目标关联、备份中的损坏业务数据、中文路径的安装器工具调用，以及退出应用时重复关闭数据库的问题。

## 执行取舍与代价（Rulings I made）

1. 用 Electron／TypeScript／node:sqlite 取代原建议的 Tauri／Rust：复用现有 Node 环境，避免先安装 Rust 和 MSVC。代价是运行包较大，架构变化时需调整本地后端。
2. 在独立的新项目目录和初始 `feature/wow-weekly` 分支直接开发，未额外建立 worktree：这里没有已有应用或 main/master 分支需要隔离。代价是开发文件直接出现在用户选择的目录；可由提交恢复。
3. 自动提交使用仅本仓库的 `Codex <codex@localhost>`：不模拟用户身份，不修改全局 Git 配置。代价是用户需要自己的提交身份时可后续更改。
4. 子代理实现和审查在 Task 1 后返回硬额度限制错误，后续改由当前会话继续实现，并保留独立审查问题和回归结果。代价是后续功能及修复没有完成独立子代理复审；报告不将其标为独立审查通过。
5. 已选来源使用约 8 秒轮询稳定读取代替原计划的文件监听去抖：在 Windows 上可处理文件替换和缺失后重新生成，仍比较摘要、校验与事务导入。代价是游戏保存后通常还需等待数秒刷新。

代码保留在本地初始功能分支，未配置远端或执行发布。为保留额度中断后的审查与恢复证据，本次没有删除计划的 SDD 工作记录。
